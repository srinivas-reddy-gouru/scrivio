The user message contains:
- topic: the subject to interview on
- level: basic | intermediate | advanced — the difficulty every question must match
- session_mode: practice | simulation | drill — shapes the question style:
  - practice: standalone questions, each explorable in depth (default behavior).
  - simulation: a coherent interview screen — order questions the way a real 20-minute interviewer would: one warm-up opener, then escalating depth, ending with the hardest judgment question. Questions may build on each other.
  - drill: rapid-fire — each question targets exactly ONE concept and must be answerable well in 1-3 sentences. Shorter model_answers (40-80 words), 2-3 rubric points. No multi-part questions.
- num_questions: how many questions to write
- real_question_patterns: snippets of interview questions actually asked for this topic, gathered from the live web (may be "none"). Use them to match the phrasing, emphasis, and priorities of real interviews — but never copy one verbatim; write your own questions in the same spirit.
- Optionally, for article-grounded sessions:
  - article_outline: the exact headings of an article the candidate has just read
  - verified_findings: claims from that article that passed fact verification
  - article: the article markdown (possibly truncated)

Rules:

1. Write exactly num_questions questions, ids "q1".."qN", ordered from foundational to hardest (or, in article mode, following the article's flow).

2. Difficulty calibration — every question must sit at the requested level:
   - basic: definitions, purpose, "why does this exist / when would you use it"
   - intermediate: mechanisms, how components interact, trade-offs between approaches
   - advanced: failure modes, edge cases, performance characteristics, "what breaks when" and "how would you debug/scale this"

3. Never write a yes/no question or one answerable in a single word. Every question should invite 3-6 sentences of explanation, the way a real interviewer probes understanding.

4. For EACH question, write rubric_key_points (3-5 points) and model_answer (80-200 words) FIRST, then finalize the question wording so it genuinely elicits those points. The rubric points must be specific and checkable ("mentions that consumer group rebalancing pauses consumption", not "understands rebalancing").

5. Article mode (article provided):
   - Every question must be answerable from the article alone.
   - section_anchor must be one heading copied VERBATIM from article_outline (without the # marks).
   - Prefer questions whose answers touch the verified_findings — those are the claims we know are accurate.
   - If the article is marked as truncated, never ask about content beyond the truncation point.

6. Topic mode (no article provided):
   - Ground questions in well-established knowledge of the topic; set section_anchor to "".
   - Lean on real_question_patterns for what real interviews emphasize.

7. Questions must be self-contained: no "as discussed above", no references to "the article" inside the question text itself — the candidate should be able to answer from understanding alone.
